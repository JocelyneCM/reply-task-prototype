    About Relay

    Relay runs short reply exercises in app-style UIs (Messenger, Email, optional legacy SMS, or audio Voice mode). Each log row is one saved event (participant message, AI reply, etc.). One full back-and-forth is a task and usually produces several rows.

    Use Study session to set the participant ID and current task; use Exports to download CSVs. The Field dictionary below lists column meanings for analysis.

    Reply register (Formal / Informal) comes from the trained formality model on participant text. Older bert_* columns in CSVs are legacy and stay empty on new rows.

    Field dictionary

    exact logged as recorded heuristic derived / estimated legacy deprecated or blank on new rows

    Raw CSV — text columns
    • reply_text — message for this row (participant or LLM).
    • participant_reply_text — same text on participant rows; empty on LLM rows.
    • llm_reply_text — same text on LLM rows; empty on participant rows.
    • final_reply_text — participant's second reply in a two-turn task/run only (empty on first participant row and on LLM rows).
    • prompt_tone / prompt_seriousness — optional; no longer back-filled from heuristics. Prefer prompt_formality (formal / informal / auto:…).
    • bert_label / bert_raw / bert_confidence — legacy columns; new rows leave them blank (older rows may still show an old HuggingFace star-sentiment demo).

    Metrics & interpretation
    • response_time_seconds — wall time from the relevant prompt being shown until the participant presses Send. For the first participant reply this anchors on the initial study prompt; for the final reply (SMS/Messenger) it re-anchors when Alex's follow-up appears, so reading/thinking after Alex is included. LLM generation time is not added to the participant's seconds (assistant rows use response_time_seconds for model latency only).
    • Typing — keystrokes/backspaces = literal keydown events (including Enter if it fires on the compose field, Shift, punctuation, etc.).
    • Swipe typing — counts are approximate OS/keyboard interaction events, not physical keys; do not compare KSPC to laptop typing.
    • Voice-to-text — keystrokes reflect manual edits after dictation, not full production effort; every qualifying keydown in the compose box is counted the same way as typing (so e.g. Shift + “1” for “!” yields multiple key events plus backspace for a deleted character).
    • WPM — (word_count / response_time_seconds) × 60 on that row, using the same response window as above (prompt shown → Send), not first-keypress → Send.
    • keystrokes_per_character (KSPC) — keypress_count / len(reply_text) for non-LLM rows. Interpretation is input-method-specific; do not treat KSPC as comparable across typing vs swipe vs voice.
    • manual_edit_count — heuristic: backspace_count + (1 if paste) + (1 if browser autocomplete). The CSV column correction_applied is only browser autocomplete / IME correction, not “the participant rewrote their message.”
    • backspaces_per_word — backspaces divided by reply word count when available.
    • edit_activity_compact — short opaque summary of edit-related flags for later aggregation (not a keylogger).
    • edit_ratio — manual_edit_count / character count of the sent reply (same caveats as KSPC).
    • MSD / EKS — need a known target sentence (copy-typing). Not used for free replies in this study.
    Formality model — where to update
    • formality_model/ — model files
    • prototype/utils/formality_service.py — loads the model
    • prototype/utils/analysis_utils.py — combines outputs before logging
    • Re-check LABEL_0 / LABEL_1 mapping if the model changes.
    Study design notes
    • Tasks may run on phone or laptop; balance phone-first vs laptop-first if needed.
    • Most input methods can be tested on both; swipe typing is phone-only.
    • Alternate or balance formal vs informal prompts to limit order effects.
    • Filter exports and log rows by participant_id, medium, input_method, prompt_formality.
